# PinEase Complete 实现说明

## 1. 功能链路

摄像头 → Worker 中的 MediaPipe → 关键点质量检查 → 几何特征 → 个体校准 → 时间状态机 → 提醒 / 计时 → IndexedDB → ECharts。

摄像头画面和逐帧关键点只存在于当前运行的内存中。模型从本地站点加载，没有上传推理帧的请求。

## 2. 特征与质量

### 正面

需要鼻子与双肩。关键点的 visibility / presence 小于 0.55 时返回未知。

- 鼻子相对肩中点的垂直位移，以肩宽归一化：低头代理。
- 鼻子与肩中点横向差：侧移代理。
- 肩线在像素尺度下的倾角：侧倾代理。
- 肩宽相对个人参考的变化：前移/距离变化代理。

镜头距离、转头、缩放和身体移动可能影响这些量。它们不是颈椎角度或真实距离测量。

### 侧面

使用较可靠一侧的耳与肩，校准后固定侧。角度按画面宽高还原同一像素单位。

髋部可见时增加髋—肩躯干线。髋部不可靠时，仅判断可靠的头颈代理，不补造躯干信息。

### 校准

采集 8 秒，以中位数建立基线，以中位绝对偏差检验稳定性。正面使用全部有效样本，检查鼻肩比例与肩线倾角；侧面选择主导侧后仍须至少 20 个有效耳肩样本，只检查头颈角度稳定性（中位绝对偏差不超过 4°），不使用双肩重叠时不稳定的正面特征。

支持近距离、略仰拍的侧面半身机位，参考角度来自个人舒适坐姿，不要求耳肩连线垂直。画面外或低置信度关键点不参与判断。髋部只有在至少 20 帧且不少于一半有效样本中清晰可见、躯干角度稳定时才建立躯干参考；否则校准头颈并明确提示本次不判断躯干。

回归检查：运行 `node --test tests/posture.test.mjs`，覆盖双肩重叠、缺失髋部、左右侧、样本不足、关键点质量与正面校准。

每种摄像头 / 正侧面组合分别保存。启动时检查画面比例，机位变化则由用户重新校准。

## 3. 时间状态机

| 状态 | 定义 | 统计 |
| --- | --- | --- |
| need_cal | 尚未建立可用参考 / 正在校准 | 不计有效监测 |
| normal | 可靠地接近参考 | 正常时长 |
| candidate_bad | 连续偏离，尚未达到提醒保持时间 | 偏离时长 |
| bad | 达到保持条件 | 偏离时长；按冷却提醒 |
| unknown | 关键点不足或识别结果过期 | 未知时长 |
| absent | 连续 5 秒无姿态结果 | 离座定义下的时长；久坐累计归零 |
| paused | 用户主动暂停 / 页面在后台 | 暂停时长；摄像头关闭 |

特征使用按时间增量的指数平滑，时间常数约 0.35 秒。持续异常默认 6 秒；恢复需保持 2 秒，使用更严格的解除阈值产生滞回。提醒默认至少间隔 90 秒。

关键点质量失效会中断候选异常，不把缺失样本当成正常或继续坏帧。超过 2.5 秒没有新结果时，计时转为未知；长时间系统挂起不补算为有效监测。

## 4. 计时与汇总

- 正常与候选/持续偏离都属于已可靠判定的有效监测。
- 良好占比 = 正常秒数 /（正常秒数 + 偏离秒数）。
- 分母为零时显示空值。
- 未知、校准、离座、暂停分别记录，不隐含算成正常。
- 久坐累计只增加可靠可判定时长；连续无姿态结果达到离座条件后重置。
- 提醒次数取实际提醒事件，不取坏帧数量。
- 记录按时间区间合并，历史图来自真实区间；日期使用浏览器本地日历。

这不能证明参与者一直在操作电脑，也不能判断注意力。产品中“专注”指一次用户主动启动的监测会话。

## 5. 眨眼参考

可选启用 Face Landmarker blendshapes。双眼闭合得分采用进入/退出两种阈值，记录短时闭合后重新睁开的事件。

最近一分钟仅用双眼入镜且连续采样的有效观察时间估计频率；相邻样本超过 150 ms 中断候选眨眼，不补算缺失时间。至少观察 20 秒且有效区间采样率不低于 8 次/秒才显示频率；画面中断或过期时显示空值。观察较充分且估计偏低时，可产生轻护眼提醒，至少间隔约 5 分钟。

界面显示实际计数、有效观察秒数和状态，便于人工核对。可选人脸推理单帧失败时返回未知，不停止坐姿监测。

模型采样不是医学设备：眼镜、转头、照明、CPU 速度和短促眨眼均可能影响结果。不会保存脸部画面或逐帧脸部数据。

## 6. 摄像头与并发

- 真实摄像头需用户手动开始并授权，音频轨道不请求。
- worker 忙时不堆积新帧，旧 ImageBitmap 及时 close。
- CPU 为 GPU 初始化失败时的回退。
- 每次启动使用代次标识，丢弃已结束流程的旧回调。
- 暂停与结束终止 Worker、停止 MediaStream 轨道并移除采集视频元素。
- 页面转入后台自动暂停；回来后手动继续。
- 修改机位、摄像头、推理节奏或眨眼开关会结束旧会话，在下一次启动生效。

## 7. 本地数据与备份

数据库为 pinease-complete，三个 object stores：

- preferences：设置。
- calibrations：参考汇总参数。
- sessions：状态区间与提醒。

会话约每 10 秒保存一次，暂停、结束与提醒时再次保存。浏览器异常关闭仍可能丢失最后尚未落盘的一小段，不承诺崩溃时的完整记录。

备份仅接受 PinEase schema 1、真实记录和限定大小/数量。导入同 ID 时保留时间信息较新的记录，避免旧备份覆盖新记录。备份不执行任何程序。

演示会话仅保留在内存，示例历史明确标注，不写入数据库或真实 CSV。

## 8. 浏览器能力边界与后续研究

- 页面内提醒及用户手动请求全屏，不控制系统亮度、其他软件或桌面置顶。
- 移动端采用响应布局，实际浏览器的摄像头和推理支持需在设备上记录。
- 本版没有自己的训练模型。后续可以用同一关键点接口比较规则、校准规则、MLP 或短时序分类器。
- 训练 / 验证 / 测试应按人员划分；不要把同一录像相邻帧打散后宣称跨人效果。
- 评估误报、漏报、提醒延迟、可判定比例、校准成功率、帧率和资源开销。
- 当前几何阈值是起点，不代表已验证的准确率。

## 9. 趣味彩蛋

仅保留倒立触发：通过眼睛、嘴部和鼻子的相对方向判断。产品页面不提供设置开关、预览入口或触发说明，也不显示“发现彩蛋”标签。触发后只显示外星人表情和“你是外星人吗？”。

动作需连续保持 2 秒；采样中断超过 750 毫秒重新计时。冷却 45 秒，持续保持同一动作只弹一次。卡片显示 5 秒，可手动关闭。暂停、结束和校准会清除彩蛋。

提示不发出声音、不发送浏览器通知、不写入提醒次数，也不改变坐姿判定。仅在真人模式的关键点清晰时判断；模型未识别到倒立人脸时不会触发，不以识别丢失代替倒立。当前版本未加入旋转画面重试，实际倒立识别效果需真人验证。旧版本保存的趣味开关在设置清洗时忽略。

## 10. 交付检查范围

已完成 TypeScript 编译、Vite 生产构建、本地 HTTP 页面响应与默认监控页面预览。

真实摄像头、各类机位下的识别效果、通知授权、真实眨眼数据、长期运行和 PWA 安装效果，仍需实际使用者在自己的设备上确认。本次没有替用户授权摄像头，也没有以演示数据冒充实测。
