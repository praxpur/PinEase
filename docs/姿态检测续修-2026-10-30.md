# 姿态检测续修记录（2026-10-30）

## 本次范围

本轮衔接当前工作区的 Full 模型、姿态通道与头姿功能，解决检查时发现的类型错误、状态机丢帧和未接通接口。未宣称完成此前执行计划的全部阶段。

## 主要改动

- 短暂无效关键点期间保留候选/确认异常的时间参考，缺口不计入保持时间；超过 750 ms 的缺口重置；确认异常恢复仍需保持恢复时间。
- 侧面校准的样本数和 6 秒覆盖范围按实际选中的主导侧计算，不再用另一侧样本掩盖该侧采样不足。
- 新会话使用统计版本 2，候选偏离与确认偏离分别累计；旧记录按原规则读取。
- 正式接通自动（Full 优先）、精细（仅 Full）、节能（仅 Lite）三种模型设置。GPU 失败时尝试 CPU；自动模式允许回退 Lite，精细模式不会静默切换。换模型后重校准。
- 人脸头姿与眨眼可独立开关，共享一个人脸模型；人脸 GPU 失败可尝试 CPU，人脸功能失败不阻断身体姿态。人脸与姿态鼻尖的图像位置不匹配时返回未知。
- 启用人脸头姿后，在校准时采集至少 20 个样本，覆盖至少 6 秒、单次缺口不超过 1.5 秒，并检查中位偏差及较大波动。参考不充分时不生成角度参考。
- 显示相对于个人参考的俯仰、左右转动和歪斜角度，标注为实验信息。结果过期或人脸不可关联时显示不可判断，**不参与姿态提醒**。
- 修复设置读入、Worker 结果类型、历史区间类型及监测页条件导致的 TypeScript 构建错误。校准写盘失败时说明仅本次有效。

## 算法与限制

人脸角度由 Face Landmarker 的 facialTransformationMatrixes 推导。MediaPipe MatrixData 默认使用列优先顺序，本次按此读取，并使用合成旋转矩阵验证混合旋转及平移不干扰旋转；数据格式参考：
https://github.com/google-ai-edge/mediapipe/blob/master/mediapipe/framework/formats/matrix_data.proto

角度的实际正负方向、不同摄像机的镜像语义、连续使用中的抖动和有效率仍待真人验证。单目变换矩阵受镜头、面部位置、眼镜、遮挡和侧脸角度影响；它不是医学检测，不保证精确测角。身体姿态主提醒仍按原有几何综合规则运行。

## 验证记录

- npm test：62 项通过，包括实际 Pinia 状态机短/长丢帧、侧面主导侧采样、候选统计、人脸参考、矩阵合成旋转、GPU/CPU 回退和功能隔离。
- npm run build：类型检查和生产构建通过。
- 使用临时隔离的无头浏览器、本地 HTTP 和人工空白画面，实际加载生产 Worker 与模型：自动模式 Full + GPU + 人脸头姿成功；节能模式 Lite + GPU + 眨眼成功。空白画面正确返回无人脸；未调用摄像头。
- 人脸检测失效、严格 Full 不自动回退、头姿与眨眼独立开关通过模拟 Worker 测试；尚未用真实摄像头验证人脸角度、长时间运行、低性能机器的 CPU 性能或多人关联。
- 校准和历史兼容由自动测试覆盖；人体/人脸数据保存在内存，历史备份仍不包含摄像头画面。

## 手动复测

在设置中启用「人脸头姿参考（实验）」后重新开始监测与校准，正面保持清晰双眼及鼻部。校准结束后小幅转头、抬头、歪头，核对相对数值与本人动作；遮挡或离开画面应显示不可判断，身体姿态监测应继续。切换 Full/Lite 后应提示重新校准。再对侧面机位检查是否得到可用人脸；不可用时应保留身体侧面检测。

本轮没有录制或使用真人摄像头数据，不能报告动作识别准确率。现有工作区包含此前尚未提交的改动和启动脚本的暂存删除；本轮未推送。
