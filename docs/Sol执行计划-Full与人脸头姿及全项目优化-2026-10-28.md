# PinEase：供 Sol 执行的升级与优化计划

日期：2026-10-28

## 1. 任务目标和执行边界

将电脑网页端和 Electron 桌面端升级为 Pose Full 主方案，引入独立的人脸头姿分析；保留 Lite 节能与回退能力。落实本次审查提出的识别、数据、提醒、UI 和结构优化。保持本地处理、原有中文产品风格和真实历史数据兼容。

本文件是执行计划，不代表任何功能已实现或准确率已提高。生成计划的当前任务不修改应用代码、不启动其他聊天、不推送或发布。后续执行者收到用户的执行授权后，按本计划实施，不需要对每项常规可逆修改重复确认。

执行前阅读适用的 AGENTS.md，检查 Git 分支、差异和最新实现。本次审查时已有 README.md 修改和启动项目.bat 的暂存删除，均不属于本计划，禁止覆盖或顺带提交。不得重置工作区，不自动推送、发布、安装或更改用户摄像头权限。

保留现有隐藏倒置彩蛋的范围，不新增可见入口或其他手势。不要把上身下沉趋势宣称为脊柱曲度、医学诊断或真实距离测量。

## 2. 已知基线和主要入口

- 当前：Vue + Pinia + Vite；Electron 复用 Web 推理；MediaPipe ES module Worker，GPU 初始化失败回退 CPU。
- 身体模型固定为 pose_landmarker_lite.task；Face Landmarker 仅在 blinkEnabled 开启时加载，当前只输出眨眼分数。
- 身体采集目标受 fps 设置控制；开启眨眼时至少按 15 FPS 调度，但实际吞吐取决于串行推理耗时。
- 已有 42 项测试和类型检查在本次审查中通过，不等于真实场景验收通过。
- 入口：src/workers/vision.worker.ts、src/lib/vision.ts、src/domain/posture.ts、src/domain/blink.ts、src/domain/types.ts、src/stores/monitor.ts。
- 数据和呈现：src/lib/storage.ts、src/lib/format.ts、src/views/*、src/components/*、src/assets/app.css、electron/*、scripts/prepare-assets.mjs。

## 3. 总体技术决策

### 3.1 模型和部署

1. 电脑网页端和桌面端默认配置以 Full 为主，Lite 为节能模式及明确可见的性能回退。Heavy 仅作为可选评测项，不进入默认安装或运行路径。
2. 网页按需加载当前模型，不在首次进入时加载所有模型；利用可版本化缓存，失败时可重试。桌面安装包内置 Full、Lite、人脸模型及配套 WASM，支持无网络运行。
3. 使用官方固定版本模型 URL；增加 Full 到资源准备脚本、资源清单和打包检查。记录来源、大小和 SHA-256；计算当前文件摘要不是完整性认证，需有独立可信的固定摘要或经过审查的资源基线。采用临时文件下载并验证后替换，失败不留下半成品。
4. 保留现有 ModuleFactory 恢复机制和取消启动的所有权隔离。模型、delegate 和功能通道的回退分别报告，不把 Face 初始化失败当成整个坐姿功能失败。
5. 模型切换会改变关键点分布：校准记录加入特征版本、模型标识及头姿算法版本。旧历史保留，旧校准标记需重建；不能静默复用或删除。
6. 性能选择依据实际耗时、结果年龄和持续运行表现，不仅判断设备类型。初始化后短暂预热，记录稳态 p50/p95；长期退化时有滞回和冷却，禁止 Full/Lite 来回切换。若需切换模型，应进入明确的重配置/重校准流程。

### 3.2 人脸、头姿和身体职责

- 将 headPoseEnabled 与 blinkEnabled 解耦；任一需要人脸的功能开启即可共享一个 Face Landmarker，不创建重复实例。
- 请求并解析人脸关键点及 facialTransformationMatrixes，辅助估计相对基准的 pitch/yaw/roll。先验证矩阵布局、旋转顺序、坐标轴、角度符号和镜像语义，不能直接套用未经确认的欧拉角公式。
- 身体负责肩线、肩髋关系、躯干倾斜及下沉趋势；人脸负责低头/抬头、左右转头、左右歪头。侧面头颈前伸使用耳肩等证据，注明二维趋势。
- 人脸结果与身体结果按时间、位置及尺度进行关联；多人进入或无法关联时暂停融合，不能把不同人的脸和身体拼在一起。
- Face 在大侧脸、遮挡时不可用，应保留可用的身体通道；姿态结果只表达已观察到的能力。转头作为状态不必自动视为坏姿态或新增提醒，默认仅持续明确偏离触发。
- 可引入 worldLandmarks 辅助角度与一致性检查，但它是单目估计，不作为精确厘米距离、脊柱形态或遮挡部位真值。

## 4. 阶段 A：补齐识别可靠性，再升级模型

### A1. 各通道独立状态

将 classify 的单个 bad/reason/deviation 改为结构化结果：每个检测项包含可用性、正常/候选/确认偏离/未知、原因、置信依据、测量值、单位、相对参考偏差。整体状态由有效通道汇总。

- 特征丢失不能作为恢复正常的证据。例如低头通道丢失后标记未知；不无限保留旧异常，也不立即显示“坐得不错”。
- 正常必须带覆盖范围，例如“头肩范围未见持续偏离”；髋部不可见时显示“躯干未判断”。
- 不混合角度和压缩百分比作为统一偏离值；若做归一化严重度，定义公式并明确不是概率或医学评分。
- 一次输出多个异常证据，UI 选稳定且优先的一项主提示，避免每帧换文案；详情显示其余项。

### A2. 时间和质量控制

- 每类异常独立累计保持时间与恢复时间，保留现有恢复滞回设计。
- 短暂无效帧暂停证据累计；超过明确缺口阈值转未知并重置。缺失区间不能补算正常或偏离。
- 使用采集时间判断时序和有效时长，结合接收时间丢弃过期、乱序和重复帧。阈值可配置并通过回放验证，不能只把新到达结果视为新鲜结果。
- 增加突跳/不合理骨段比例检查；平滑按有效时间和质量工作，避免把极低质量点平滑成可信数据。
- 将关键点模型分数与最终动作可信度区分；各特征使用其依赖点的质量，不能用鼻肩质量代表髋部或头姿质量。
- 重新定义 candidate_bad 的历史统计口径：候选不直接冒充确认异常；建议未知/候选独立保留，新旧统计版本明确兼容，并更新历史说明和导出字段。

### A3. 校准升级

- 从固定倒计时+20样本，改为有效时间覆盖、连续稳定窗口、采样间隔和有效样本数联合验收。失败时指出缺少面部、耳、肩或髋，不重复无信息的“再试一次”。
- 对所有参与判定的特征检查稳定性，补齐 shift、scale 等；保存中位数、MAD/分位数范围及各通道覆盖率。
- 个人阈值采用基础下限与校准噪声容差结合，并限制上限；噪声太大应要求改善机位，不能无限放宽。
- 检查机位/方向与选择模式一致；保留正面、侧面和设备独立参考。
- 摄像头平移、倾斜、缩放或人体尺度同步突变时提示参考可能失效；区分“怀疑机位改变”和“已确认姿态偏离”。不无条件自动学习新的基准。
- 校准只建立个人参考，不宣称校准时姿势已经被判定为健康。

## 5. 阶段 B：Full + Face 落地与识别扩展

### B1. Worker 和采集协议

- init 参数加入模型档位、headPoseEnabled、blinkEnabled；响应报告实际模型、delegate、通道可用性和降级原因。
- 帧协议携带采集时间、身体/人脸各自的结果时间、耗时、可选 worldLandmarks、头姿数据与质量标志。只传使用的数据，避免传输大量无用数组。
- 身体与人脸分开调度、限频，共享输入和 Face 实例。若不同步采样，设最大融合时间差；无结果不是“没眨眼”或“姿态正常”。
- 身体以 10–15 FPS 为初始试验目标；眨眼另行评估短促动作漏计和最低有效采样要求。不要为了低耗电强制降帧后仍展示可信眨眼频率。
- 继续使用 Worker、busy 背压和 bitmap.close，确保只有一帧在途或有明确有界队列。记录丢帧和结果年龄，不无限排队。
- 处理模型下载、CPU 回退、Face 失败、切档取消、路由卸载、摄像头中断和快速启停，不破坏既有回归保障。

### B2. 检测项和覆盖条件

| 检测项 | 主要证据 | 限制 |
| --- | --- | --- |
| 低头/抬头 | 相对校准的人脸 pitch，鼻耳关系辅助 | 人脸不可用时只显示可靠的替代趋势 |
| 左右转头 | 人脸 yaw | 普通看副屏默认不直接触发坏姿态提醒 |
| 左右歪头 | 人脸 roll 与肩线关系 | 与身体侧倾分离 |
| 肩线倾斜 | 双肩高度差 | 不能直接等同脊柱侧弯 |
| 躯干侧倾 | 肩中点—髋中点方向 | 肩髋清晰才能启用 |
| 上身前倾/后仰 | 侧面肩髋方向，三维估计辅助 | 保留机位与遮挡质量门槛 |
| 头颈前伸趋势 | 侧面耳肩关系，头姿辅助 | 不输出未经验证的厘米数 |
| 上身下沉/收拢趋势 | 相对高度、多特征一致性 | 不能等同含胸或脊柱曲度测量 |
| 更靠近摄像头趋势 | 多尺度证据及方向一致性 | 肩宽单一变化不足以确定屏幕距离 |

### B3. 回退与用户设置

提供“自动（优先 Full）/精细（Full）/节能（Lite）”，说明实际使用模型、通道覆盖及重校准要求。自动回退要有可见原因，手动精细模式失败不可偷偷声称仍在使用 Full。模型切换不伪造旧会话的连续检测。

## 6. 阶段 C：完成原有功能和数据交互修复

1. 桌面提醒：增加受限 IPC 和 Electron 原生通知；点击返回窗口。最小化/隐藏时仍可收到提醒；提供试听和测试通知，处理系统不支持/拒绝。默认不擅自开启声音。去重与冷却覆盖页面、声音、系统通知，避免三路重复轰炸。
2. 演示退出：区分当前监测模式和历史数据源；结束演示恢复真实记录。历史“返回我的记录”必须真的返回真实数据，退出不需要先打开摄像头。演示不污染真实历史和提醒统计。
3. 设置生效：标注即时生效、下次生效、需重启的项目。对模型/摄像头/运行节奏/人脸功能等需要重启项，提供集中应用和明确的会话结果，不能切换一个开关便无说明结束监测。
4. CSV：与当前筛选范围及当前会话快照一致，按选择导出7天或30天；统一字段术语和候选/未知口径，记录导出时点。
5. 历史列表：取消无提示 slice(0,30)，增加分页/加载更多、真实总数和已展示数量；保持排序稳定。
6. 保存失败：持久化返回成功/失败，不能吞错后仍声称已保存；设置页和全局都可见警告，区分“本次已应用”和“持久化成功”，提供重试/备份。
7. 备份：明确“历史备份”与“完整备份”的范围。若扩展为包含设置、模型配置和校准，版本化 schema，保留旧历史备份导入；校准按设备/模型兼容性决定是否需重新校准，不能直接激活外部旧基准。

## 7. 阶段 D：UI、可视性和信息结构

- 未开始保留欢迎说明；开始后折叠大介绍区，摄像头、当前状态、检测覆盖和控制按钮成为首屏中心。
- 统一一套阶段驱动的操作规则：准备设备、等待校准、校准中、监测中、暂停、失败。消除上下两处主按钮语义不一致；等待校准不显示“正在监测”。
- 主控制区靠近预览；窄屏确保暂停/结束易找到，必要时使用不遮挡内容的固定控制区。设置/历史中也可看到真实运行状态和暂停入口。
- 提高关键说明字号：状态说明目标13–14px，辅助文字目标至少12px；不要保留移动端8–9px的关键信息。实测浅色/深色对比度和键盘焦点，不仅凭视觉猜测。
- 校准显示已完成的有效进度、缺失部位和当前可启用能力。监测显示“头姿可用/躯干不可用”等，而非单一绿色清晰指示。
- 设置提供分组导航，高级项折叠，修改处就地反馈；需要中断监测的项目提前说明。
- 历史图表增加可访问数据表/数值摘要；遵循减少动画偏好，包括 ECharts 动画；空数据、模拟数据和无效观察区间清楚区分。
- 文案保持“相对参考”“趋势”“暂不可判断”，减少“良好/舒适/正常”混用造成的评价歧义。
- 保留现有绿色自然视觉风格，不进行无关品牌或页面重做。

## 8. 阶段 E：有边界地重构

按职责逐步提取 camera/vision、calibration、posture channels、session/history、reminder、persistence；Pinia 保留界面门面和明确的会话协调职责。模块名称可按现有目录调整，不为拆文件而拆文件。

统一真实历史、当前会话、演示和示例的数据选择器。会话转换集中处理，避免各组件分别推导启动/结束/校准规则。历史聚合按变更频率适当缓存，避免每帧遍历全部历史。

统一字号、颜色、状态色、间距、焦点 token，合并重复移动端覆盖规则。重构期间持续保证既有回归测试，不一次性推倒 store 或换框架。

## 9. 测试、实测与验收门槛

### 9.1 自动化验证

- 新增能验证行为的回归：通道缺失不能判恢复；短缺口/长缺口；不同异常独立计时；过期/乱序帧；不稳定校准与时间覆盖不足；模型版本切换；镜像和头姿角度符号；人脸身体关联失败；异常并存。
- 验证 Lite/Full、GPU/CPU、Face失败、下载失败、连续启停、路由切换、后台暂停、桌面锁屏/退出保存；不能只检查源代码里是否出现字符串。
- 数据回归：旧版本备份、校准迁移、保存失败反馈、CSV范围和当前会话、超过30条历史、演示退出。
- 执行 npm.cmd test、npm.cmd run type-check、npm.cmd run build；必要时构建桌面包并核验 ASAR 模型/WASM/许可证资源齐全。

### 9.2 真实场景对照

在获得授权的测试素材上，使用相同视频、相同判定规则对比 Lite 与 Full；Heavy 为可选评测，不作为交付阻塞。素材覆盖不同参与者、正面/侧面、光线、眼镜、半身/髋部可见、遮挡和近距离桌面机位。日常运行仍不保存摄像头画面；额外录制测试视频必须单独获用户授权，也可使用合规公开或用户提供素材。

必须包含正常打字、看副屏、喝水、捡物、耸肩、转椅、离座、摄像头移动，以及各目标姿态和多种异常并存。按参与者分离调参与验证数据，避免同一人的相似片段泄漏。

记录关键点丢失率/静止抖动、每小时误提醒、事件漏报率、提醒延迟、有效检测覆盖率、各类别混淆情况，以及 p50/p95 推理耗时、结果年龄、实际 FPS、CPU/GPU/内存和长时运行情况。不能只报告帧准确率，也不能靠大量标记未知来制造低误报。

电脑网页端与 Electron 分别至少做一次持续30分钟测试；记录机器、浏览器/Electron、GPU/delegate、模型与设置。Full 是否适合作默认，以实际收益和持续运行能力决定；若目标设备不达标，保留明确的Lite回退并如实记录。

真实设备或素材不足时，完成代码、自动化验证和可执行测试步骤，把未测项标为“待验证”。不得编造准确率、耗电数据或把合成测试包装成真人实测。

### 9.3 UI验收

检查桌面常用窗口、900×680最小桌面窗口、窄屏320/390/720宽度、200%缩放、日夜主题、键盘操作和减少动画。检查无横向溢出、按钮可达、状态文案真实、保存失败可见、图表可读；摄像头权限不允许时也能完成演示和设置操作。

## 10. 推荐执行次序与交付

按 A → B → C → D → E 推进；模块提取可随 A/B 小步进行，避免在最后机械搬代码。每阶段先建立具体行为测试，再落地相应实现并验证。模型资源与协议应在依赖的识别逻辑启用前完成。

最终提交给用户：

1. 已实现/待验证清单，逐项映射本计划。
2. 模型选择与回退说明、资源来源与版本、校准迁移说明。
3. 测试命令及实际结果、真实设备评测表或明确待测清单。
4. UI关键状态截图，以及导出/备份兼容性说明。
5. 剩余限制和下一步所需素材，不宣称未测性能与准确率。

不要把每个功能的实现都阻塞在一次大验收上；也不能因为核心识别完成就丢弃本计划中的UI和数据问题。只有完成相应验证的项才能标记完成。
